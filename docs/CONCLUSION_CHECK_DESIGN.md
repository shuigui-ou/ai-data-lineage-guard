# 结论层校验设计（v0.4.0 · 已按实现前修正回改）

> 状态：**已实现（v0.4.0）**，`verify_conclusions.py` + 已接入 `emit.py` 落盘前置。本文先钉死"能查什么、查不到什么、怎么查"，避免又变成一个"看起来能查"的假闸门。
>
> **v0.4.0 修正记录（实现前，用户提出，全部接受）**：
> 1. **裸数字检测降级为提示级**，且只在 `basis` 字段内强制；误报率实测 <10% 后才考虑把「basis 内裸数字」升级为硬拦。
> 2. **阈值自声明的规避路径**（AI 可声明 `p<=0.99` 自我通过）写入诚实边界；缓解手段：`threshold` 必须带 `source` 字段留痕可审。
> 3. **claim `id` 必须唯一**（重复即报错）；**方向一致性只查显式矛盾**，不验因果方向。

## 0. 一句话

**结论真伪大多没有 ground truth，但"结论有没有绑定可核验的数字、证据链自不自洽"有 ground truth。**
→ 校验对象不是"结论对不对"，而是**"结论的证据链是否成立"**。

## 1. 切分：结论 = 可核验成分 + 不可核验成分

一条结论（judgment）天然是两件事混在一起：

| 成分 | 例子 | 能不能机械查 | 归谁 |
|---|---|---|---|
| **证据成分** | "依据 311 行样本、cooccur 总和 5613、命中行号 [1,4,6,…]" | ✅ 能（数字全部可回溯到源） | 下沉到现有三层 |
| **判断成分** | "因此该传导关系成立/显著/值得买" | ❌ 不能（无 ground truth） | 标注为人工拍板 |

**做法**：强制结论声明时把两者分开写，证据成分挂 `evidence` 引用，判断成分挂 `verdict` + `verifiability`。

## 2. 四类结论 × 可核验性分级（关键设计）

不是所有结论都同等可查。按**判断成分的 ground truth 强度**分四档：

| type | 例子 | 判断成分可核验吗 | 机械可查的部分 | 分级 |
|---|---|---|---|---|
| `arith` 算术结论 | "总额 = 5613" | ✅ 完全可（就是数字对账） | 全量可查 | **下沉第 1 层** |
| `derived_stat` 统计结论 | "均值 18.05"、"占比 42%" | ✅ 可（可从源重算） | 全量可查 | **下沉第 1 层** |
| `lookup` 查表结论 | "E298 的 lift = 367.0"、"该实体是 E298" | ✅ 可（查源行） | 全量可查 | **下沉第 1 层** |
| `relational` 关系结论 | "A 与 B 显著相关"、"传导成立" | ⚠️ 部分（阈值/样本量/方向可查，"显著"本身要判定规则） | 证据链 + 阈值一致性 | **新第 4 层** |
| `causal` 因果结论 | "A 导致 B" | ❌ 不可（相关≠因果） | 只能查"它引用的证据是否存在且自洽" | **新第 4 层，只查引用完整性** |
| `recommend` 建议结论 | "建议买入"、"值得配置" | ❌ 不可（价值判断） | 只能查"依据数字是否与叙述一致" | **新第 4 层，只查引用完整性** |
| `forecast` 预测结论 | "明天会涨 2%" | ❌ 不可（未来无真值） | 只能查"输入状态是否有出处" | **新第 4 层 + 事后回测** |

**这张表是整个设计的核心**：它决定"哪个结论该进哪道闸门"，而不是给所有结论套同一个检查。

## 3. 新增第 4 层：结论链自洽检查（可机械做）

命名：`verify_conclusions.py`（提示级还是硬拦级？见 §6）

### 3.1 引用完整性（硬）
- 结论引用的每个 `evidence` id 必须**存在于** claims 集合 → 引用不存在 = ❌ 悬空引用
- 被引用的 claim 必须**已通过**第 1 层机械对账（PASS）→ 引用了 FAIL 的证据 = ❌ 证据本身有问题
- 同一 evidence id 不能既当"支持"又当"反证"（`stance` 字段冲突）→ ❌
- **claim `id` 必须唯一**（修正 3）：重复 id 即 ❌ 报错。否则"引用了哪个"有歧义，
  结论可以挑对自己有利的那个（绕过检查）。

### 3.2 数字一致性（**提示级** ⚠️，不是硬拦 —— 修正 1）
- **第一版走 ⚠️ 提示，不硬拦。**
  理由：全文扫数字的误报率很高——"过去 3 年""前 5 名""Q2""第 2 季度""增长 3 倍"
  都会被扫到，而这些**未必是"没标注来源的数字"，只是叙述性表达**。
  假拦截的代价已定过：**假拦截 → 逼人绕过 → 整道防线失效**。
- **分级**：
  - `basis` 字段内的数字 → 可溯源要求**严格**（这是证据区，本该每个数都有出处），
    但**第一版仍是 ⚠️ 提示**；实测误报率 <10% 后再考虑升级为 ❌ 硬拦。
  - `statement` 正文叙述里的数字 → **放过**（只提示，不拦）。
- 技术实现：从 `statement` / `basis` 正则抽数值 token（支持千分位、百分数、带单位）
  → 逐个在"被引用 evidence 的可重算集合"里找匹配。
  - 匹配到 → ✅
  - 找不到 → ⚠️ 疑似裸数字（**提示级**）
  - **不判定该数字"该不该在这里"**（那需要语义判断 → 交第 3 层）

### 3.3 阈值一致性（可机械，但要声明判定规则）
`relational` 类结论必须声明判定依据：
```json
{"type": "relational", "verdict": "显著相关",
 "criterion": {"metric": "n", "op": ">=", "value": 100,
               "source": "本次判定依据：样本量≥100（依据已核验 claim c2）"},
 "evidence": ["c1","c2"]}
```
检查：从证据算出 metric 的实际值，与 criterion 比对 → 结论说"显著"但样本量 42 < 100 = ❌ 自相矛盾。

**关键**：criterion 是**结论自己声明的**，脚本不发明标准（这跟用户"系统不发明模板"一致）。脚本只查"你声明的标准，你自己的数据满足吗"。

**⚠️ 修正 2 的缓解手段**：`threshold`/`criterion` **必须带 `source` 字段**
（引用哪条规范 / 哪个已核验 claim / 哪份文档），**至少留痕可审**。
宽阈值不再"隐形"——白纸黑字留着，事后能追。

### 3.4 方向一致性（硬，但**只查显式矛盾** —— 修正 3）
结论若含方向词（"上升""下降""正相关""负相关"），必须能从证据推出该方向：
- 证据是 `from_node/to_node` 的传导值，结论说"上升" → 比对符号
- 结论说"负相关"但证据 lift > 0 → ❌

**边界（修正 3 明确）**：结论说"A 导致 B"而证据是相关系数时，
脚本**无法判断因果方向对不对**，只查"**结论声称的方向与证据里显式声明的方向是否矛盾**"。
→ 第 4 层**不能验因果**，别让人误以为它能。

### 3.5 因果/建议类：只查引用完整性
`causal` / `recommend` / `forecast` 类**不查真伪**，只查：
- 引用完整性（同 3.1）
- 数字一致性（同 3.2，**提示级**）
- 并且**必须显式标注 `verifiability: "manual"`** → 没标 = ❌（防止把不可核验的结论伪装成可核验的）

## 4. schema 设计（向后兼容）

现有 claim 加**可选** `id` 字段；新增可选顶层 `conclusions` 数组。

```json
{
  "claims": [
    {"id": "c1", "label": "cooccur 总和", "value": 5613,
     "derived": {"op": "sum", "col": "cooccur"}},
    {"id": "c2", "label": "样本行数", "value": 311,
     "derived": {"op": "countrows", "col": "edge_id"}}
  ],
  "conclusions": [
    {"id": "k1", "type": "relational",
     "statement": "该节点对下游有稳定传导",
     "verdict": "显著",
     "criterion": {"metric": "n", "op": ">=", "value": 100},
     "evidence": ["c1", "c2"],
     "stance": "support"},
    {"id": "k2", "type": "recommendation",
     "statement": "建议在当前窗口配置该方向",
     "verdict": "可配置",
     "verifiability": "manual",
     "evidence": ["c1"]}
  ]
}
```

**向后兼容**：`claims` 无 `id` → 结论机制不启用（现有行为一字不变）；有 `conclusions` 但 `claims` 无 id → 报"结论引用需要 claim 带 id"。

## 5. 结论里的数字怎么抓（关键技术点）

结论的 `statement` 是自由文本，里面数字可能写成：
- `5613` → 直接数值
- `5,613` → 千分位
- `18.05%` → 百分数
- `5613 元` → 带单位

**做法**：正则抽出文本中的数值 token → 逐个在"被引用 evidence 的可重算集合"里找匹配。
- 匹配到 → ✅
- 找不到 → ❌ 裸数字（无出处）
- **不判定该数字"该不该在这里"**（那需要语义判断 → 交第 3 层提示级）

## 6. 分级：结论层该硬拦还是提示？（按修正 1 调整）

**建议分层，不搞一刀切**：

| 检查 | 级别 | 理由 |
|---|---|---|
| 引用完整性（悬空引用 / 引用了 FAIL 的证据 / id 重复） | **硬拦** | 纯逻辑错误，无歧义，不拦等于放行假证据 |
| 结论里的裸数字（`basis` 内 / `statement` 内） | **⚠️ 提示** | **修正 1**：全文扫数字误报率高（"过去 3 年""Q2""前 5 名"），假拦截会逼人绕过 → 防线自毁。实测误报率 <10% 后才考虑把 `basis` 内升级为硬拦 |
| 数字矛盾（结论说 5613，证据是 5612） | **硬拦** | 纯事实矛盾 |
| 阈值一致性（自称"显著"但样本量不足） | **硬拦** | 自相矛盾，无歧义 |
| 方向一致性（只查显式矛盾） | **硬拦** | 自相矛盾；**不验因果方向**（修正 3） |
| 因果/建议类的真伪 | **不查** | 无 ground truth |
| 措辞/口径/逻辑跳跃 | **提示** | 交第 3 层语义审计（fresh-context） |

**硬拦的四项（无歧义、不会误伤）**：引用完整性、被引证据未 PASS、数值矛盾、方向矛盾。

**为什么不一刀切提示**：这四项是**纯逻辑/纯事实**，机器判定没有歧义，判错就是程序 bug。这类留成提示等于闸门失效。
**为什么因果/建议不查**：真伪无 ground truth，机器判 = 编造第二份真值（重蹈语义审计"重算"覆辙）。


## 7. 与现有三层的分工（不重复）

| 层 | 锚点 | 查什么 | 谁做 |
|---|---|---|---|
| 1 机械对账 | 值 ↔ 单元格 | 数值对不对 | 脚本（硬） |
| 2 落盘闸门 | 产出通道 | 能不能落盘 | 脚本（硬） |
| 3 语义审计 | 单元格 ↔ 语义实体 | 指的实体/时间/单位/指代对不对 | 独立 LLM（提示） |
| **4 结论链检查（新）** | **结论 ↔ 证据链** | **结论有没有证据、证据自不自洽** | **脚本（分级：多数硬） |

**结论层的独特价值**：前三层都只看**数字**，第 4 层是唯一看**"结论与数字的绑定关系"**的层。

## 8. 诚实边界（写死在 SKILL.md）

- **不能保证结论是对的**。只能保证"结论引用的数字确实来自源数据、且彼此不矛盾"。
- **相关性 ≠ 因果**：criterion 只查"你声明的判据你满足吗"，不查"你的判据本身对不对"。
- **阈值是结论自己声明的**：脚本不发明显著性标准。若 AI 声明 `n>=5` 就算显著，脚本只查"n 确实 ≥5"——**判据宽窄是人的责任，机器只查自洽**。
- **方向判断仅限符号可查的情况**：涉及阈值/口径的"方向"仍需语义层。
- **第 4 层依赖第 1 层通过**：证据没通过机械对账，结论层一律报 FAIL（不做二次判定）。
- **裸数字检测是保守近似**：可能把叙述性数字（如"过去 3 年""Q2""前 5 名"）误报 → **第一版就是 ⚠️ 提示级**，实测误报率 <10% 后才考虑把 `basis` 内升级为 ❌ 硬拦。
- **⚠️ 自声明阈值可被放宽以规避（修正 2 的核心边界）**：脚本只查"你声明的标准，你的数满足吗"。
  AI 完全可以声明极宽阈值让自己通过——`criterion: {metric: "p", op: "<=", value: 0.99}`，
  p=0.5 也自洽 → PASS。**机器判断不了"0.99 这个阈值合理吗"，那是领域知识，是人的责任。**
  缓解手段：`criterion` **必须带 `source` 字段**（引用哪条规范 / 哪个已核验 claim / 哪份文档），
  宽阈值不再"隐形"，而是白纸黑字留痕可审、事后能追。
  （不改设计：改成系统发阈值就变成塞模板了。）
- **⚠️ 证据选择偏差查不出来**：AI 只引用支持自己的证据、漏引反证，
  引用完整性对此**无能为力**——每条被引证据都合法 PASS，但选择本身有偏。
  → 这类只能靠**抽查**（人工看结论是否漏引了反证），不靠脚本。
- **第 4 层不能验因果**：结论说"A 导致 B"而证据是相关系数时，
  脚本**无法判断因果方向对不对**，只查"结论声称的方向与证据里显式声明的方向是否矛盾"。

## 9. 实现顺序建议

1. 给 claim 加**可选** `id`（向后兼容，一字不改现有逻辑）
2. `verify_conclusions.py` 实现 §3.1/3.2/3.3/3.4（硬）+ §5 裸数字检测

## 10. 实现结果与实测（2026-10-24）

### 已落地
- `verify_conclusions.py`（第 4 层）+ `verify_lineage.py` 加 `check_claim_ids()`（id 唯一性，id 可选向后兼容）
- `emit.py` 接入：claims 文件含 `conclusions` 时自动跑第 4 层，硬拦项 FAIL 则**不落盘**、隔离报告带 `[H1..H4]` 理由
- 样本：`samples/conclusion/`（源表 = 预测系统真实 10 条传导关系；正例 + 5 个阴性对照 + 误报探针）

### 实测结果
| 样本 | 期望 | 实测 |
|---|---|---|
| 正例（真实结论 R01：n=798, p=2.9e-11, d=0.318） | PASS | ✅ exit 0 |
| neg1 悬空引用 + id 重复 | FAIL | ✅ exit 1 [H1] |
| neg2 阈值矛盾（要求≥100 实际10） | FAIL | ✅ exit 1 [H3] |
| neg3 数值矛盾（结论800 证据798） | FAIL | ✅ exit 1 [H2] |
| neg4 方向矛盾（称负 证据正） | FAIL | ✅ exit 1 [H4] |
| neg5 因果类未标 manual | FAIL | ✅ exit 1 [H1] |
| 误报探针（全叙述性数字） | PASS | ✅ exit 0（裸数字只提示不拦） |
| 第 1 层既有 7 项回归 | 不退化 | ✅ 全过 |

### ★ 裸数字误报率实测 = **100%**（9/9）
探针样本只用叙述性数字："过去 3 年""前 5 名""Q2""第 2 季度""2019 至 2026""8 个年度窗口""增长约 3 倍"
→ 全部被判"无出处"。
**结论：远高于 10% 阈值 → 维持提示级，不升级为硬拦**（实证支持修正 1）。
若将来要降误报，方向是**词法白名单**（年/季度/名/倍/窗口/区间等语境词）而非放松判定。

### 实现中踩的 3 个真 bug（自测抓不到，靠跑对照样本暴露）
1. **方向词误判**："该关系下行样本量为 800"里的"下行"是**样本分组名**（n_down），不是方向主张
   → 误把 H2 数值矛盾报成 H4 方向矛盾，**判定理由完全错**。
   修法：方向词须处于「效应/变化量」语境（GROUP_CONTEXT / EFFECT_CONTEXT）。
   修第一版又修过头（"下行**方向**表现…"被误杀，因单字"中"被当分组语境）→ 分组语境收紧为**成词匹配**。
   方向检测用例 9/9 通过。
2. **小数值精度丢失**：`round(v, 6)` 把 p=2.9e-11 抹成 **0.0** → p 值核对失效。
   修法：保留原值 + 相对容差比较。
3. **H2 数值矛盾最初没实现**：设计稿列为硬拦四项之一，但首版只做了 W1 裸数字（提示级），
   → 数值矛盾只报 ⚠️ 不拦。**靠 neg3 阴性对照暴露**（"结论说 800、证据 798"没被拦）。
   修法：W1 扫描时若证据里存在"数值接近但不相等"的候选（相对差 <5%）→ 升级为 H2 硬拦。

### 教训
**"设计稿写了"不等于"实现了"**——H2 就是设计稿明确列为硬拦、实现时漏掉的。
靠**阴性对照**（每条只坏一处）才暴露出来，这是自测样本（只测对的情况）永远给不了的。

## 11. v0.5.0 实施结果（2026-10-24）

本轮三项改动同批落地，全部有实测数字，不靠"应该没问题"。

### 11.1 词法白名单（降 W1 误报）

**改前**：误报探针 9 条叙述性数字全被判"无出处" → **误报率 100%（9/9）**。
**改后**：**0/9**。

判据按**词法上下文**（左右邻字），只放过"不可能是被研究量的测量值"的数字：

| 规则 | 放过的形态 | 例子 |
|---|---|---|
| R1 季度标签 | 前一字符是 Q/q | `Q2` |
| R2 年份/年份区间 | 后接"年"；或处于 1900–2099 的"至/到"区间 | `2019 至 2026 年间` |
| R3 序数/排名 | 前接 第/前/首/末/名列/top | `第 2 季度`、`前 5 名` |
| R4 时段计数 | 后接时间单位 + 前有"过去/最近/连续"等标记 | `过去 3 年`、`最近 12 个月` |
| R5 窗口/区间计数 | 后接**结构词**（窗口/区间/周期/批次/时段） | `8 个年度窗口`、`2 个交易日区间` |
| R6 倍数(带约数词) | 后接"倍" + 前有约/近/超等 | `增长约 3 倍` |

**不放过的**（反向测试 0/8 假阴性，真信号一条没漏）：
样本量、金额、百分比、效应量、均值、收益率、**无约数词的倍数**（`增长 3 倍` 是量级主张）、
**无结构词的计数**（`涉及 5 个交易日` 是实体计数，不是窗口计数）。

**关键设计**：白名单在**比对之前**判。若放在之后，"第 800 名"会因与证据 798 接近被 H2 判成
"数值矛盾"——**理由完全错**（那不是抄错，是排名）。硬拦的理由必须准确，宁可放过不可误拦。

**诚实边界**：白名单是词法的不是语义完美的。"第 800 名"会被放过——但放过比误报硬拦更正确。

### 11.2 语义审计扩展到结论措辞与逻辑跳跃

清单从 4 项扩到 6 项（声明级 4 + 结论级 2）：新增 `wording`（措辞强度撑不住证据）、
`leap`（相关→因果 / 样本内→样本外 / 历史同期→未来 / 有限区间→普遍）。

备料包新增三样**确定性提取**的东西（只标"出现了什么"，**不下判断**）：
- `evidence_magnitude_hints`：被引证据按「像效应量 / 像显著性 / 像样本量」分组的原值
- `wording_markers`：强措辞词出现情况（带否定守卫，"不显著"不算）
- `leap_markers`：跳跃词分 causal / future / universal / sample_scope 四类

**真实试跑（fresh-context 独立实例，双臂对照）**：

| 臂 | 结论内容 | 结果 |
|---|---|---|
| 脏臂 | k1「大幅且决定性」+ k2「导致/未来/所有/必然」 | **7 条线索**（wording 3 / leap 3 / unit 1），k3 未报 |
| 净臂 | 同一批证据，措辞改为「中等强度正相关（cohen_d=0.318），统计检验 p=2.9e-11」等克制表述 | **0 条线索** |

→ 审计者有判别力，不是"只会报问题"的装饰品。

### 11.3 Parquet 源支持

`pyarrow` 可选依赖，缺则 exit 3 干净报错；分批读（`iter_batches`）不爆内存；
列名取 schema（空表也报错）；值统一转字符串（NaN/None → `""`）；损坏文件不漏 traceback。

**等价性实测**：同一份数据存 csv 与 parquet，两分支**对账结论逐条一致**。
注意口径是**数值等价**不是字面相等——csv 的 `amount` 是文本 `"100"`、parquet 是 float64 → `"100.0"`，
数值都是 100.0。这条差异由回归用例 `t_parquet_equivalence` 显式断言（数值列比数值、非数值列比字面）。

### 11.4 回归入口（本次新增）

`tests/run_all.py` —— 18 个用例一条命令跑完。**之前每轮改动都是手工跑几个命令，没有可复现入口**；
"我跑过了"不是证据，"任何人任何时候跑这条命令得到同样结果"才是。

**跳过必须显式计数**：发布包内不放二进制样本（xlsx/parquet），第三方解压后这些用例会跳过。
若不计数，"18/18 通过"会掩盖"其中 6 个根本没跑"。
- 完整环境（openpyxl + pyarrow）：**通过 18 ｜ 跳过 0**
- 纯净环境（仅标准库）：**通过 12 ｜ 跳过 6**（跳过明细打印在汇总里）

**第三方解压包测试暴露的真缺陷**（本地跑不会暴露）：发布包不含 xlsx/parquet 样本，
但回归用例直接引用它们 → 第三方解压后 `t_lineage_xlsx_no_cache` 崩在 FileNotFoundError。
修法：`_need()` 守卫 → 样本缺失时显式跳过并说明，不静默 fail、不静默 pass。

### 11.5 本轮踩的坑（4 个真 bug，都由对照暴露）

1. **效应量列分类只看 label → 中文 label 全漏**：`effect_down_rel_median` 被归到 `other`，
   因为 label 是"R01 下行中位效应"不含英文 "effect"。修法：分类优先取 `source.col` 真实列名。
2. **去重逻辑把元组当词用**：`extract_markers` 返回 `(位置,词)` 元组，去重时 `seen.add(w)` 加的是元组，
   输出一堆 `[(37,'大幅'),(40,'决定性'),(49,'决定性')]`。修法：`for _, w in hits`。
3. **R4/R5 首版漏判 3/10**："最近 12 个月"（后缀是"个月"不是"月"）、"共覆盖 2 个交易日区间"、
   "覆盖 8 个年度窗口"（尾部要剥"个/年度"量词前缀）。
   修的过程中差点造成假阴性：若按"个交易日"整体放行，"涉及 5 个交易日"（实体计数）会被放过 →
   改为只认**结构词**（窗口/区间/周期/批次/时段）。
4. **等价性断言过严**：csv `"100"` vs parquet `"100.0"` 字面不同被判不等价。
   修法：数值列比数值、非数值列比字面 —— 这才是"等价"的正确定义。

### 教训
**"能跑通"不等于"可用"**：本地跑通 18/18 的包，第三方解压后崩 6 个。
**跳过数不计数 = 假 PASS**：18/18 里藏 6 个没跑，比明说"12 通过 6 跳过"更危险。
