# AI 数据核对（ai-data-lineage-guard）

**用了这个 skill，AI 统计/汇总数据时不会瞎说、不会偷懒。**

它不敢凭记忆编数、不会把数字抄错、不会把单位或实体搞混——因为它交活时每个数字都必须写明出处，
再由独立脚本拿你的原始数据逐条核对，对不上的直接拦住，文件都不给你落盘。

你拿到的每个数字，都能一键回溯到原始数据。

## 快速上手

```bash
# 1. 让 AI 按协议产出结构化结果（每个数字带血缘标签）
#    claims.json 示例：
#    {"claims": [
#      {"label": "A产品金额", "value": 100, "source": {"row": 1, "col": "amount"}},
#      {"label": "金额总额",   "value": 350, "derived": {"op": "sum", "col": "amount"}}
#    ]}

# 2. 通过产出通道落盘（不通过校验，交付文件写不出来）
python emit.py --source data.csv --claims claims.json --out 报告.md
```

## ⚠️ 最容易踩的坑

**它不检查你现有的报告，它要求你按协议产出。**
直接丢一份没有血缘标签的普通报告进去，会拿到 `exit 2` ——
那是「**没按协议写**」，**不是**「检查通过」，也不是「工具坏了」。

## 四层闸门

| 层 | 工具 | 锚点 | 级别 |
|---|---|---|---|
| 1 机械对账 | `verify_lineage.py` | 值 ↔ 单元格 | **硬拦**：FAIL 不落盘 |
| 2 落盘闸门 | `emit.py` | 唯一产出通道 | **硬拦**：不通过就写不出文件 |
| 3 语义审计 | `audit_semantic.py` | 单元格 ↔ 语义实体<br>结论措辞 ↔ 证据强度 | **提示**：出线索走人工复核 |
| 4 结论链 | `verify_conclusions.py` | 结论 ↔ 证据链 | **分级**：H1–H4 硬拦 / W1 提示 |

- **第 1 层**抓：抄错（值≠源单元格）、算错（派生重算不符）、编数、来源缺失。
- **第 2 层**让「正确路径」成为唯一能产出有效交付物的路径。
- **第 3 层**抓机械抓不到的：单位混淆（中/万元）、时间窗口错位、指代错位、实体身份错位（标签写"华东"但那行是"华南"，金额碰巧相同）；
  以及**结论措辞撑不住证据**（说"大幅"而效应量是中等）、**逻辑跳跃**（相关→因果、历史同期→未来）。
- **第 4 层**查"基于数字得出的结论"：结论必须绑定已核验的数字（`evidence` 引用带 id 的 claim）、
  claim id 必须唯一、结论里的数字不能与证据"接近但不相等"、自声明判定依据必须带 `source` 留痕；
  因果/建议/预测类强制标注 `verifiability: "manual"`（不可核验的结论不得伪装成可核验的）。

**为什么语义审计不做硬拦**：LLM 审计本身会误报。拿概率性判断当硬闸门会制造假拦截，
假拦截会逼人绕过闸门，整道防线反而失效。所以——**AI 出线索，人拍板**。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 通过 |
| 1 | 有错位/无法验证 → 不落盘，写 `.blocked.md` |
| 2 | **未按协议写**（未解析到带标签的数值声明） |
| 3 | 源数据无法加载 / 依赖缺失 |

## 数据源

- `.csv` / `.json`：零依赖，纯标准库
- `.xlsx` / `.xlsm`：需 `openpyxl`（只读）。缺依赖**显式报错**，不静默降级
- 公式单元格无缓存值 → **显式报错**，绝不假 PASS

## 适用范围与诚实边界

**适用**：结构化数值产出的核对——统计表、汇总数字、报表指标、清单数值。
**不适用**：自由文本质量校验、代码正确性验证、非数值内容。

- 只在 **有限真实任务 + 若干样本**上验证过，**发布不等于验证充分**。
- 抓不到"值和来源被同时写错且恰好自洽"的极端情况。
- 语义审计**不保证召回**：可能漏、可能误报。价值是"盲区从没人看变成按清单留痕"，不是清零。
- 第 4 层**不能验因果方向**；自声明阈值可被放宽以规避（机器只查自洽、不查阈值合理性，那是领域知识）；
  证据选择偏差（只引支持自己的证据）查不出来，靠人工抽查。
- **漏采的文件根本不在备料包里**，任何校验都对它视而不见——覆盖度要另做"源文件全集 vs 已采集合"的显式对账。
- 裸数字检测的词法白名单是**词法的、不是语义完美的**："第 800 名"会被放过（语义是排名不是测量值）。
- 纯协议层强制；**真·硬闸门需框架级 pre-delivery hook 调 `emit.py`**。

## 目录

```
SKILL.md                 完整协议（含 mermaid 流程图）
SEMANTIC_AUDIT_PROMPT.md 语义审计者提示词（交 fresh-context 独立实例）
verify_lineage.py        第一层：机械对账
emit.py                  第二层：产出通道闸门
audit_semantic.py        第三层：语义审计（提示级，含结论措辞/逻辑跳跃）
verify_conclusions.py    第四层：结论链检查（H1–H4 硬拦 + W1 提示）
tests/run_all.py         一键全量回归（18 用例，跳过数显式计入）
tests/test_whitelist.py  词法白名单双向测试（真信号不漏 + 叙述数字放过）
build_dist.py            打包（纯文本 zip，无图片）
skillhub_meta.json       发布元数据
PUBLISH_CHECKLIST.md     上架自检清单
samples/                 演示数据（含 conclusion/ 与 semantic/ 两组对照样本）
trial/                   试跑证据（含真实项目数据验证记录，不发布）
```
